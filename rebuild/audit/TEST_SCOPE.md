# 검사 범위 재평가

검사 통과는 해당 입력·조건에서의 단언을 통과했다는 뜻이다. 설계 전체의 깊이·완결성·재미·모든 상태 조합을 검증한 것으로 확대하지 않는다.

이번 1단계에서 새로 실행한 것은 `scripts/audit-rebuild.js`의 코드 목록 추출·고정 시드 메모리 관찰과 요구사항 근거/문서 링크 확인이다. 아래 기존 검사들은 소스의 단언과 조건을 읽어 보장 범위를 조사했다. 이전 작업에서 통과했던 검사라도 이번 문서 조사에서 모두 다시 실행한 것으로 표시하지 않는다.

## 이번에 재현한 관찰

원본 출력은 [source-inventory.json](source-inventory.json)의 `probes`에 있다.

| 관찰 | 입력/방법 | 결과 | 해석의 한계 |
| --- | --- | --- | --- |
| 새 시작 규모 | createGame(17).view() | 60명·3지역·9부지·3경로·3상품·3정당 | 실제 요구 규모와 완성도를 뜻하지 않음 |
| 목표 변경의 영향 | 같은 상태에서 목표만 바꾸고 각각 하루 진행 | people·firms·plans가 같음 | 문자열 저장 외 계획 연결이 없다는 소스 추적과 함께 판정 |
| 학습값 영향 | 같은 새 상태에 서로 다른 g/q를 넣어 하루 진행 | 뷰가 같음 | 모든 미래 동작의 실험 증명은 아님. 소스에서 읽기 경로도 확인 |
| 원본 보관과 주택 | 40명 원본 변환 | 원본 전체 일치, 기존 주택 18채에 대응하는 새 주택 객체 없음 | 원본 보존 검사와 권리 이전 검사는 구분해야 함 |
| 나이·날짜 이전 | 유효 주민의 나이를 6세, 원본 날짜를 123일로 둔 통제 표본 | 새 주민 18세·새 날짜 0일 | 정상 마이그레이션의 연속성이 현재 보장되지 않음을 보여주는 사례 |
| 기존 행동/사건 표면 | seed19·120명에서 가문 시작 | 목록 105개·현재 실행 가능 61개, 사건 정의 638개 | 해당 인물/시점의 목록. 전 역할의 전체 행동 수나 전수 실행 수가 아님 |

## 후속 검증이 채워야 할 경계

1. **상태 준비 없이 생기는 과정:** 주민·경쟁자·정당이 같은 규칙으로 목표·자원·협상·실행을 수행하는지.
2. **여러 경로의 비교:** 다른 입지·사업·정치·가문 경로가 각각 지속 가능한지, 결과 차이가 선택의 원인으로 설명되는지.
3. **원래 권리·의무의 연속성:** 진행 중인 부채·지분·소유·관계·사건이 변환·저장·복원 이후 실제로 작동하는지.
4. **대표 장애·경합:** 자금과 권한 변경, 동시 명령, 담당자 이탈, 파일 손상·중단·저장 실패가 반영 일관성을 지키는지.
5. **전체 기능을 켠 규모 검증:** 원래 학습과 다양한 산업·세력·계약이 있는 상태의 장기간 시간·메모리·화면/health 응답.
6. **사용자의 판단 흐름:** 핵심 작업 발견→비교→실행→결과 이해→복귀를 역할별로 직접 수행하는 검증. 단순 무오류나 버튼 존재와 구분.

어떤 검사가 아직 없는지는 [80개 요구의 통과 시나리오](REQUIREMENTS.md)로 추적한다. 1단계에서 검증이 없는 부분을 구현된 것으로 승격하지 않는다.
