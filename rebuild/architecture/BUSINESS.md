# 6단계 — 사업·공급망·물류·경쟁 (진행 중)

기준 main은 PR #69 병합 커밋 `d5c6b5316e28ffab65eb7930c6056a707b9355e1`이다. **6단계 전체 완료가 아니다.** 회사 자금·실제 공급/운송/입고에 이어, 같은 시설의 창고 재료→계약 직원의 하루 노동→공정/품질→실제 고객 지출→회사 손익, 반복 공급과 중단 화물의 대체 운송, 집터 사이 통행로를 사용하는 도로 물류와 사업장별 창고 운송을 연결했다. 작업은 초안 PR #70에서 이어간다.

기존 공개 채용·해고·임금·설비·지분/금융 기능도 회사 문맥에서 연다. 물리적 창고 공정을 켠 회사는 사장 개인 재고 생산/소득의 회사 이체와 매출 비례 추상 가산을 사용하지 않는다. 과거 사건/건물 행동의 직접 매출 가산 진입점도 차단하고 실제 거래에 연결되지 않은 옛 시장·납품·수출·리콜 사건은 이 운영 방식에서 생성하지 않는다. 설비는 실제 공정 효율, 광고는 실제 고객 도달/발견에 연결하고 표시도 고쳤다. 아직 실제 권리/시설에 연결하지 않은 기존 지점·연구·재단·어두운 경영의 일괄 가산 행동은 이 운영 방식에서 실행을 막는다. 다른 기존 회사와 classic의 기존 계산은 그대로 둔다.

## 상태·하루·회계 소유권

주민·개인/회사 현금·고용·주식·건물·시간의 기준은 기존 `engine.js`다. 새 인구·지갑·별도 하루 계산을 만들지 않는다. 창고 공정은 **기존 하루의 직원 실행 슬롯**을 사용하고 기존 개인 생산/품팔이를 같은 날 중복 수행하지 않는다. 실제 숙련 증가와 피로, 임금·세금·연금 및 노동 통계도 같은 슬롯에서 처리한다. 계약 만료나 공무/복무/학업으로 출근할 수 없는 직원은 공정에 억지로 투입하지 않는다.

`S.business`에는 발주 신원/화물, 회사 창고의 재고·품질·매입원가·시설 위치, 생산/판매 방침·관측, 임금채권, 반복 발주 조건과 최근 기록을 저장한다. 계약 등록부는 공급·추가 운송·고용·임금채권의 신원/상태를 같은 원본에 연결하며 새 지갑으로 사용하지 않는다. 미리보기/실패는 세계·난수·계약·물품·임금·자동 발주까지 복구하고 중복 요청은 재집행하지 않는다.

매입 원가는 실제 물품 대금+운임(회수 운임 포함)을 실제 입고 수량으로 나눈 이동평균이다. 재료를 소비하면 원가를 완제품에 옮기며 **임금은 당기 비용**으로 처리한다. 영업손익은 실제 상품/시설 이용료 매출−팔린 물품의 원가−회사 임금 지출−저장 손실−광고/복지/보수 등의 관측 운영비다. 원재료 매입 대금을 다시 전액 비용으로 이중 차감하지 않는다. 이전 저장에 원가가 없으면 현재 시세로 추정하고 UI에 명시한다. 하루 계산 뒤 수동으로 지급한 광고비 등의 운영비는 다음 일 보고에서 한 번만 인식하고 미반영 금액을 UI에 표시한다. 현금 지급은 지시 시점에 이미 완료된다. 이 운영 손익은 투자·차입·배당·자금 지원 등 회사 현금 변화 전체와 구분한다.

회사의 양의 운영 소득에는 기존 정부 기본 소득세율(최대 60%)을 적용한다. 실제 회사→국고 납부와 미납 채무를 보존한다. 근로자에게는 기존 개인 소득세·연금 계산을 사용한다. 모든 제도의 업종/지역별 법령·면세·세무 분쟁을 구현한 것은 아니며 해당 제도는 9~10단계와 연결한다.

곡식/식사는 기존 저장 규칙에 맞춰 창고·운송/대기 중 손실을 반영한다. 실제 저장 시설이 있으면 보관 손실을 줄인다. 화물이 소진되면 손실 상태를 남기고 0으로 나눠 잘못된 원가/품질을 만들지 않는다. 건물이 없어지거나 회사가 정리되어도 화물·창고·임금채권을 삭제하지 않는다. 재고/화물/체불/미납 세금/기업 대출이 남은 회사의 임의 청산과 자동 폐업 배분도 막는다. 체불/미납 세금이 있는 회사는 자동 대표 보수·배당과 수동 배당을 먼저 지급하지 않는다. 임금채권의 수령인은 기존 `die()`가 정한 상속인만 사용한다. 상속인이 다시 사망하면 같은 채권 지분을 재승계하고, 상속인이 없으면 실제 정산금을 `unclaimedCash` 유산 계정에 보관한다. 상속 당시 세율을 채권에 보존해 정산 시 상속세를 실제 국고로 옮기며 상속분을 근로소득으로 다시 과세하지 않는다. 과거 저장에서 이미 사망해 당시 수령인 기록이 없는 채권은 보존하고 추정 지급을 거부한다. 계약 등록부에도 수령 지분/승계 기록을 반영한다. **전체 자산 매각·채권 순위/비례 배당·주주 잔여재산·무연고 유산의 최종 귀속까지 포함한 폐업/상속 정산은 아직 남아 있다.**

## 공간과 저장 경계

회사의 창고는 **사업장별**로 분리한다. 원래 회사 키의 창고를 그대로 유지하고 추가 사업장에는 별도 `warehouseId`를 사용해 물품/원가·계정 신원을 중복하지 않는다. 회사 방침에서 실제 생산 시설을 선택하며 해당 시설 창고의 재료만 소비한다. 다른 창고로 바꾸면 재고가 이동하지 않고, `business.transfer`가 출발 창고→실제 운송 화물→도착 창고로 옮긴다. 상품 대금을 재지급하지 않고 운송인에게 실제 운임만 지급하며 이전 매입 원가+새 운임을 입고 원가에 반영한다. 반복 발주도 승인된 입고 시설의 재고·운송량만 본다. 위치가 없는 옛 재고는 입고 기록/단일 설비로 확인하며 불명확한 다중 시설 재고를 자동으로 새 창고에 합치지 않는다. 회사당 동시에 활성화하는 생산 방침은 아직 하나이며 여러 생산 공정을 시설마다 동시에 편성하는 기능은 후속 작업이다.

새 화물은 `geo.lots`의 집터 사이 통행 간격으로 만든 **동일한 도로 그래프**를 지도·운임/납기·실제 이동에 사용한다. 각 구간 길이가 이동 비용이고 포장 수준이 이동 속도에 반영된다. 기본 구간 용량은 하루 화물 40개이며 당일 초과 화물은 현재 교차점에서 기다린다. 한 운송인은 공급처로 이동해 화물을 인수한 후 실제 경로로 입고하고 실제 귀환 경로까지 다른 일을 하지 못한다. 폐쇄 구간은 교차점에서 다시 경로를 찾고 전체 단절이면 현재 위치에서 기다리며 도로 복구 뒤 재개한다. 운송 중 화물/방문 출입로와 폐쇄/용량 포화 구간을 같은 지도에 표시한다. 위치는 구간 끝 교차점으로 관리해 폐쇄된 구간에서 다른 길로 순간 이동하지 않는다. 이전 거리 방식의 운송 중 화물은 기존 경로를 도착까지 유지한다.

이는 기존 집터 간격을 통행로로 정한 초기 공간 모델이며, 플레이어가 사유지에 도로를 임의로 건설하는 권한을 만들지는 않는다. 도로 폐쇄·용량은 전체 저장에 보존하지만 새 도로의 토지 권리·건설/정비 예산과 인력·재난/전쟁의 구간 피해·공적 통제 UI는 아직 연결하지 않았다. 단절/용량 충격 검사는 통제 상태로 명시한다. 이 후속 제도까지 완성했다고 세지 않는다.

canonical envelope는 **v6**이며 v1/v2/v3/v4/v5를 읽고 기존 주민/g/q/재산/계약/시간을 보존한다. 도로 진행값과 사업장별 재고를 모르는 이전 실행기가 새 저장을 정상 저장으로 열지 않도록 버전을 올렸다. native `exportState()`의 v1 형식과 classic 저장 경로는 바꾸지 않았다. 손상된 방침/재고/채권/도로 경로·진행값을 거부하며 새 세계로 덮어쓰지 않는다.

business 조회는 요청 시 Worker에서 gzip 응답하며 일반 `/view`에 전체 이력이나 주민 g/q를 넣지 않는다. 공급 후보는 회사 주변 가용 운송인 16명과 품목별 제안 3개, 채용 후보는 8명, 표시 이력/회수 목록은 제한한다. 원본 인구·학습·권리 자료를 줄인 것이 아니며 모든 운송 대안의 전역 최적화를 보장하지 않는다.

## 검증
