# 6단계 — 사업·공급망·물류·경쟁 (진행 중)

기준 main은 PR #69 병합 커밋 `d5c6b5316e28ffab65eb7930c6056a707b9355e1`이다. **6단계 전체 완료가 아니다.** 회사 자금·실제 공급/운송/입고에 이어, 같은 시설의 창고 재료→계약 직원의 하루 노동→공정/품질→실제 고객 지출→회사 손익, 반복 공급과 중단 화물의 대체 운송을 연결했다. 작업은 초안 PR #70에서 이어간다.

기존 공개 채용·해고·임금·설비·지분/금융 기능도 회사 문맥에서 연다. 물리적 창고 공정을 켠 회사는 사장 개인 재고 생산/소득의 회사 이체와 매출 비례 추상 가산을 사용하지 않는다. 과거 사건/건물 행동의 직접 매출 가산 진입점도 차단하고 실제 거래에 연결되지 않은 옛 시장·납품·수출·리콜 사건은 이 운영 방식에서 생성하지 않는다. 설비는 실제 공정 효율, 광고는 실제 고객 도달/발견에 연결하고 표시도 고쳤다. 아직 실제 권리/시설에 연결하지 않은 기존 지점·연구·재단·어두운 경영의 일괄 가산 행동은 이 운영 방식에서 실행을 막는다. 다른 기존 회사와 classic의 기존 계산은 그대로 둔다.

## 상태·하루·회계 소유권

주민·개인/회사 현금·고용·주식·건물·시간의 기준은 기존 `engine.js`다. 새 인구·지갑·별도 하루 계산을 만들지 않는다. 창고 공정은 **기존 하루의 직원 실행 슬롯**을 사용하고 기존 개인 생산/품팔이를 같은 날 중복 수행하지 않는다. 실제 숙련 증가와 피로, 임금·세금·연금 및 노동 통계도 같은 슬롯에서 처리한다. 계약 만료나 공무/복무/학업으로 출근할 수 없는 직원은 공정에 억지로 투입하지 않는다.

`S.business`에는 발주 신원/화물, 회사 창고의 재고·품질·매입원가·시설 위치, 생산/판매 방침·관측, 임금채권, 반복 발주 조건과 최근 기록을 저장한다. 계약 등록부는 공급·추가 운송·고용·임금채권의 신원/상태를 같은 원본에 연결하며 새 지갑으로 사용하지 않는다. 미리보기/실패는 세계·난수·계약·물품·임금·자동 발주까지 복구하고 중복 요청은 재집행하지 않는다.

매입 원가는 실제 물품 대금+운임(회수 운임 포함)을 실제 입고 수량으로 나눈 이동평균이다. 재료를 소비하면 원가를 완제품에 옮기며 **임금은 당기 비용**으로 처리한다. 영업손익은 실제 상품/시설 이용료 매출−팔린 물품의 원가−회사 임금 지출−저장 손실−광고/복지/보수 등의 관측 운영비다. 원재료 매입 대금을 다시 전액 비용으로 이중 차감하지 않는다. 이전 저장에 원가가 없으면 현재 시세로 추정하고 UI에 명시한다. 하루 계산 뒤 수동으로 지급한 광고비 등의 운영비는 다음 일 보고에서 한 번만 인식하고 미반영 금액을 UI에 표시한다. 현금 지급은 지시 시점에 이미 완료된다. 이 운영 손익은 투자·차입·배당·자금 지원 등 회사 현금 변화 전체와 구분한다.

회사의 양의 운영 소득에는 기존 정부 기본 소득세율(최대 60%)을 적용한다. 실제 회사→국고 납부와 미납 채무를 보존한다. 근로자에게는 기존 개인 소득세·연금 계산을 사용한다. 모든 제도의 업종/지역별 법령·면세·세무 분쟁을 구현한 것은 아니며 해당 제도는 9~10단계와 연결한다.

곡식/식사는 기존 저장 규칙에 맞춰 창고·운송/대기 중 손실을 반영한다. 실제 저장 시설이 있으면 보관 손실을 줄인다. 화물이 소진되면 손실 상태를 남기고 0으로 나눠 잘못된 원가/품질을 만들지 않는다. 건물이 없어지거나 회사가 정리되어도 화물·창고·임금채권을 삭제하지 않는다. 재고/화물/체불/미납 세금이 남은 회사의 임의 청산도 막는다. **완전한 폐업·상속 권리 정산은 아직 남아 있다.**

## 공간과 저장 경계

현재는 회사의 **같은 입고 시설**에서 생산하는 단일 창고 모델이다. 다른 부지의 설비가 생겼다고 기존 회사 재고를 순간 이동해 소비하지 않는다. 위치가 기록되지 않은 옛 재고는 입고 기록으로 확인하며, 기록 없는 단일 설비 재고의 배정은 방침 확인 화면에서 알린다. 여러 부지의 옛 재고를 임의로 합쳐 새 위치를 만들지 않는다.

운송은 공급자·운송인·입고 건물의 실제 좌표 거리와 마을 포장 수준으로 납기·운임을 계산한다. 실제 도로 그래프·구간 용량·교통 단절을 계산한 것으로 취급하지 않는다. 중단 화물의 위치도 현재 거리 모델의 운송 진행값이며 GPS나 도로 위 실측 좌표가 아니다. 실제 도로 및 다중 창고 간 운송은 다음 구현이다.

canonical envelope는 **v4**이며 v1/v2/v3를 읽고 기존 주민/g/q/재산/계약/시간을 보존한다. 사업 공정과 임금/세금 상태를 모르는 이전 실행기가 새 저장을 정상 저장으로 열지 않도록 버전을 올렸다. native `exportState()`의 v1 형식과 classic 저장 경로는 바꾸지 않았다. 손상된 새 방침/재고/채권은 거부하며 새 세계로 덮어쓰지 않는다.

business 조회는 요청 시 Worker에서 gzip 응답하며 일반 `/view`에 전체 이력이나 주민 g/q를 넣지 않는다. 공급 후보는 회사 주변 가용 운송인 16명과 품목별 제안 3개, 채용 후보는 8명, 표시 이력/회수 목록은 제한한다. 원본 인구·학습·권리 자료를 줄인 것이 아니며 모든 운송 대안의 전역 최적화를 보장하지 않는다.

## 아직 남은 6단계 완료 조건

1. **실제 도로/시설 물류:** 연결·단절·경로·구간 비용/용량·혼잡이 지도 및 공급 부족과 일치해야 한다. 현재 거리/포장 총량 모델은 이 조건을 충족하지 않는다. 다중 시설/창고 간 실제 이동도 필요하다.
2. **기업 관계·권리:** 기업 간 공급·동업/분담·공급/회수 조건 협상·반복 계약의 책임/배상, 재고의 기업 평가/주주 권리와 폐업 창고·화물·체불·사망 직원 채권의 완전한 정산을 통합한다. 현재 보존과 일부 실행 거부를 전체 권리 정산으로 세지 않는다.
3. **충격·경쟁의 장기 플레이:** 공급 독점/중단·대체 조달·가격/고용/체불 전파와 회복을 여러 기업·지역·시드에서 검증한다. 현재 24일 통제 전략 비교와 8일 반복 공급을 전체 경제의 장기 자립성 검증으로 세지 않는다.
4. **6단계 최종 연결 검사:** 일반 시작·여러 시드·5,000명·전체 기능 규모·모바일/저장/재개에서 같은 목표에 지속 가능한 전략 2개 이상과 비용/위험 차이를 확인한다.

7~14단계도 남아 있다. PR #70을 자동 병합하거나 AWS 서비스를 재시작하지 않는다.
