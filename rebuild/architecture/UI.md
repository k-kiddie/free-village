# 4단계 — 실제 지도와 모바일 기본 플레이

현재 생활 기능·지역 경제·저장 v3와 검증 범위는 [5단계 기록](LIVING.md)을 따른다. 아래 내용과 관측값은 해당 단계 당시의 기록이다.

완료 범위는 **기존 기준 세계에 연결한 지도·대상 상세·비교·생활 지침·사업 시작·행동 미리보기/실행·결과/복귀와 HTTP/저장 연결**이다. 진입 주소는 `/rebuild`이며 기본 인구는 5,000명이다. 사업 운영·물류·자율 세력·협상·정치·가문 등 5~12단계의 확장은 이 화면을 기반으로 이어간다.

## 실행 경로와 저장

`/rebuild` → `rebuild/play.html` + `play-client.js` → `/rebuild/api/*` → `server.js`의 단일 활성 Worker → `rebuild/play-worker.js` → 3단계 `core/session.js`, `commands.js` 및 기존 `engine.js`.

저장은 **`save/canonical.json.gz`**로 분리한다. 기존 `rebuild.json.gz` 시제품, `village.json.gz`, `god.json.gz`, 편집실 저장을 덮어쓰거나 자동 변환하지 않는다. 기본 `/`·`/play` 주소는 아직 시제품이다. 기본 주소 전환과 전체 저장 이전은 13단계 통합 뒤에 한다.

새 Worker는 조회·미리보기·실행·저장 요청을 한 큐에서 처리한다. 실행 성공 후 기존 gzip/fsync/rename 저장이 끝난 뒤 응답한다. 자동 저장·사용자 저장·세계 전환/종료 저장도 같은 큐를 사용한다. 읽을 수 없는 기존 저장은 새 세계로 덮어쓰지 않는다. 응답을 잃으면 브라우저의 보류 요청을 같은 commandId로 재전송한다. 저장 실패 시에도 새 행동으로 넘어가지 않고 이전 요청의 결과 확인을 먼저 한다.

브라우저에는 엔진을 넣지 않았다. 전체 주민의 g/q를 계산·보관하는 곳은 Worker다. 일반 화면 응답과 지도 데이터에는 g/q를 보내지 않으며, 선택한 주민의 상세 요청에서만 기존 공개 범위 안의 전체 주민 데이터를 제공한다.

## 화면과 실제 데이터

| 화면 | 구현한 작업 |
| --- | --- |
| 마을 지도 | 실제 `S.geo.lots/terr`, `PLOTS`, 집·건물·공방·공사·주민의 위치를 Canvas에 표시. 지도 이동/확대·전체/주민/자산 레이어·내 위치·접근 가능한 대상 목록 |
| 대상 상세 | 주민·주택·농지·집터·건물·공방·공사·회사 조회. 실제 소유자/거주자·매매/임대/보증금·상태·공사 진행과 연결 주민을 표시. 해당 대상에 기존 엔진이 제공하는 행동만 연결 |
| 주민 찾기 | 전체 주민 이름 검색과 40명 단위 페이지. 지도에 표시를 줄인 주민도 찾아 선택 가능. 미공개 인물의 재산/학습을 추정해서 보여주지 않음 |
| 비교함 | 최대 3개 대상의 같은 revision 자료를 비교. 지도 위치·선택을 유지하고 대상 상세로 복귀. 카메라와 비교 대상은 세계별로 로컬 보관 |
| 생활과 일 | 식량·건강·배고픔·실제 일 지침과 하루 결과. 품팔이/벌목, 장사/농사, 주민 판단의 우선순위를 기존 엔진이 허용하는 값으로 설정. 실제 모집이 생기면 계약 일감도 표시 |
| 가문 금고 | 개인 현금과 분리한 보관·인출의 실제 비용/잔액 비교와 실행. 응답 유실 시 중복 집행 방지 |
| 사업 시작 | 건물 마련→공사 진행→회사 설립의 조건과 비용을 검색·확인·실행. 기존 매물·차입·예금·주식의 선택지도 표시. 없는 자금·직원·건물·기술을 UI가 만들어내지 않음 |
| 행동/결정 | 3단계 실행기의 실제 자격·비용·재고·대기 기간을 미리보기. 난수를 쓴 표본은 확정 수익으로 보여주지 않음. 거절 이유·실행 전 재검사·결과를 같은 흐름에서 확인 |
| 활동과 결과 | 저장된 성공 영수증과 내 관련 소식을 다시 조회. 실제 금액 변화와 재사용 대기 기간을 표시. 실행 후 이전 화면이나 활동 기록으로 이동 |

주민 표식은 활동 대상·집·작업 장소·시장/숲/채석장 중심에 놓는다. 같은 장소의 주민을 가짜 좌표로 흩뜨리지 않고 목록으로 구별한다. 도로는 기존 지도와 같은 시장 중심 연결 표현이며, 새 물류/도로 경로 비용 계산을 구현했다는 뜻은 아니다. 움직이는 보간 애니메이션은 이번 범위에 없다.

## 조회·명령 API

| 요청 | 내용 |
| --- | --- |
| `GET /rebuild/api/view` | worldId/revision/day, 내 상태·일 지침·결정·공사·회사·최근 활동. gzip/ETag와 Worker의 마지막 뷰 캐시 사용 |
| `GET /rebuild/api/map?x=&y=&w=&h=` | 지정 범위의 실제 지형·공간 및 최대 300명+내 인물 표식. 전체/표시 수를 명시하며 전체 상세를 섞지 않음 |
| `GET /rebuild/api/people?page=&q=` | 40명 페이지의 ID·이름·위치. 학습·전체 주민 상세를 보내지 않음 |
| `GET /rebuild/api/detail?kind=&id=` | 선택한 대상만 상세 조회. 없어진 대상은 404 |
| `GET /rebuild/api/catalog?target=` | 실제 동적 행동·선택 후보. 가능 여부는 해당 입력의 미리보기로 확정 |
| `POST /rebuild/api/preview`, `/execute` | 기존 공통 명령 계약. 새 `advance`도 미리보기 토큰·revision·중복 방지를 사용하는 정확히 하루 명령 |
| `POST /rebuild/api/cmd` | 사용자 저장만 허용. 임의 Worker 메서드나 전체 체크포인트 조회를 노출하지 않음 |
| `POST /rebuild/api/session` | 접속 수명 관리. 기존 저장 후 종료·단일 Worker 전환 체계와 연결 |

하루 명령은 기존 `world.step()`을 정확히 한 번 사용한다. 주민 전체의 변화가 계산되지만 응답/영수증의 회계·재고 변화는 내 인물·가문·운영 회사로 제한한다. NPC 전체 장부를 매일 전송하거나 명령 이력에 복제하지 않는다. 하루의 자연 시뮬레이션에는 기존 엔진의 채무/음수 잔액 규칙을 유지하고, 별도 사용자 지출 명령의 잔액 사후 검사는 유지한다.

## 통과한 검사

- `node scripts/check-canonical-view.js`: **5,000명** 실제 집터 좌표와 대상 소유자, 선택 상세의 g/q, 전체 주민 페이지, 조회 전후 전체 저장·난수 불변, 하루 명령·저장 복원. 시드 42의 해당 시작 상태에서 view 1,210B / 전체 지도 313,806B / 하루 결과 1,159B(JSON, 압축 전)를 관측했다. 크기는 세계 상태에 따라 달라진다.
- `node scripts/check-canonical-http.js`: **기본 512MB Worker·5,000명 시작**의 실제 서버. 경량 응답/ETag 304·지도·페이지·상세, 자격 거절, 하루 명령, 전체 g/q gzip 저장, 기존 세계로 전환 후 같은 세계·날짜·학습 복원, 활성 Worker 1개. 모바일 Chromium에서 엔진 없는 화면 렌더·대상 선택·가로 넘침도 확인했다. 출생·이주로 인구가 늘어도 실제 인구와 전체 저장을 보존한다.
- `node scripts/check-canonical-ui.js`: 모바일 Chromium **390×844**에서 시작 결정→지도 대상/주민 선택→비교/복귀→일 지침 비교/실행→하루 진행, 금고 이체의 응답 유실/재전송, 직원 자격 부족 거절, 건설 시작→공사 완료→회사 설립→활동 결과. 실제 저장과 서버 재시작 복원, Origin 제한·비공개 경로 거절, **1440×1000** 레이아웃도 확인했다.
- UI 검사의 사업 경로는 현금 30,000을 준 100명 fixture다. 기존 주민·g/q·공간·생산·실제 공사 기간은 유지했다. 공사 대기 40일과 그 사이 결정 처리는 같은 공통 명령 API로 진행했으며, 모바일에서 버튼 40회를 눌렀다는 뜻은 아니다. 무자본 시작의 장기 경제 균형을 검증한 것으로 취급하지 않는다.
- `check-common-commands.js`, `check-canonical-session.js`: 이전 단계의 자격·미리보기 불변·복구·중복 집행·저장/난수 보존 회귀를 확인했다. `engine.js`와 기존 생성 `index.html`은 이번 단계에서 수정하지 않았다. 기존 `check-http.js`의 5,000명 상세/저장/ETag와 `check-worlds.js`의 마을↔가문 4회 전환·Worker 1개·저장 분리·종료 저장 검사도 통과했다.

화면 캡처는 `/workspace/artifacts/stage4-map-mobile.png`, `stage4-compare-mobile.png`, `stage4-results-mobile.png`, `stage4-desktop.png`, `stage4-5000-mobile.png`다. 이는 Linux Chromium의 모바일 크기 검사이며 실물 iPhone/Android 및 AWS 배포 검사와 구별한다.

## 남은 범위

5단계 생활·지역 경제를 시작으로 수요·기술·교육·부양·이주·지역 차이의 인과를 보강한다. 이후 사업/공급망·조직·계획·협상·정치·가문 화면을 실제 시스템과 함께 확장한다. 모든 역할의 UI, 전체 이전/편집실/삽화, 장기 전체 기능 성능·실물 휴대폰·실제 디스크 장애·AWS 운영은 아직 완료하지 않았다. 기본 주소 전환·main 병합·AWS 배포도 하지 않았다.

## 일반 시작 경로 추가 검증·결함 수정

이전 검사의 자금 fixture/API 대기 구간을 보완했다. `node scripts/check-normal-play-ui.js`는 **빈 저장·시드 42·기본 5,000명**으로 시작하며 자금·직원·기술·공사 진척을 주입하지 않는다. 초기 자금은 69냥이었다. 실제 차입(100+30냥), 건설, 하루 진행, 도중 결정 5건, 회사 설립을 모두 모바일 크기 Chromium의 화면 버튼으로 처리했다. **41일 UI 진행** 후 첫걸음상사를 설립했고, 종료 현금은 16.428474094797355냥, 생존 인구는 5,375명이었다. 차입 없는 창업이나 모든 시드의 성공을 보장하는 검사는 아니다.

20일째 공사 중 서버를 종료/재시작해 같은 날짜·세계·진척에서 이어갔다. 여기서 발견한 실제 결함을 수정했다.

- 기존 엔진은 사망자를 정리하기 전 `agents`의 전체 기록과 `dead`의 참조용 기록에 함께 저장한다. 이를 잘못된 중복으로 거부하던 검증기를 수정했다. 같은 목록 내 중복과 생존자/사망자 충돌은 계속 거부한다. 전체 자료와 g/q를 삭제해 회피하지 않았다. `check-transient-dead-save.js`가 이 저장/복원을 재현한다.
- 인구·지도·주민 찾기는 생존자를 표시하고 사망 원본 자료는 저장에 유지한다.
- 사업 화면 안에서도 하루를 진행하고 공사 진척을 볼 수 있게 했다. 날짜 변경·재접속 뒤 검색어가 유지되며, 조회가 끝나기 전에 입력한 검색어도 반영한다.
- 처리 중 새 버튼이 준비된 것처럼 보이고 빠른 다음 클릭을 무시하던 문제를 수정했다. 버튼의 처리 중 상태와 화면 낭독기 상태를 표시한다.

기존 모바일 비교·반응 유실/재시도·자격 거절·회사 설립 검사와 공통 명령/저장 회귀도 다시 통과했다. 실물 휴대폰·AWS 운영 검증을 했다는 뜻은 아니며, 그 외부 검증은 남아 있다. 이어서 5단계 생활·지역 경제를 수행한다.
