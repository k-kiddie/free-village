# 프리빌리지 리빌드 — 구현과 검증

2026-11-20. `REBUILD_PLAN.md`의 8단계를 구현하고 아래 명령과 실제 HTTP·Chromium 흐름으로 확인했다. 이 기록은 코드·로컬 실행 검증이며 AWS 실서버 배포 완료를 뜻하지 않는다.

## 실행과 진입점

Node.js 22 이상, 런타임 외부 의존성 없음.

```sh
PORT=8080 node server.js
```

| 주소 | 기능 | 저장 |
| --- | --- | --- |
| `/`, `/play` | 새 전략 게임 | `save/rebuild.json.gz` |
| `/editor` | 같은 규칙을 실험하는 별도 세계 편집실 | `save/rebuild-editor.json.gz` |
| `/classic` | 기존 자유방임 시뮬레이션 | `save/village.json.gz` |
| `/god` | 기존 가문 게임, 정합성 수정 포함 | `save/god.json.gz` |

서버는 새 게임으로 시작한다. `INITIAL_WORLD=village`는 기존 서버 검사·운영 호환을 위한 초기 세계 선택이다. 동시에 활성화되는 Worker는 하나이며, 세계 전환은 이전 세계의 저장 완료 후 진행한다.

## 1. 구조 조사 — 완료

| 대상과 코드 근거 | 결정 |
| --- | --- |
| `engine.js`: `createWorld`, `dynStart`, `dynActions`, `dynStoryTick` | 주민 학습·경제·가문 행동이 하나의 클로저에 결합돼 있다. 기존 시뮬레이션은 유지하고 새 플레이의 경제·시간·권한은 독립 엔진으로 교체했다. 두 경제를 동시에 실행해 중복 지급하지 않는다. |
| `sim-worker.js`: 엔진 전용 지도 DTO, `server-presenter.js`와 기존 HTML 의존 | 새 `rebuild/worker.js`가 같은 Worker 프로토콜을 구현한다. HTTP 계층과 단일 Worker 전환을 재사용한다. |
| `server-storage.js`: `writeSnapshot` | 스트리밍 gzip·fsync·임시 파일 원자 교체를 재사용한다. |
| `god-client.js`, `ui2.html`: 기존 탭·검색·팝업 | 새 `client.js`·`index.html`로 교체한다. 지도와 대상 패널을 함께 두며, 기존 UI는 호환 주소에서 유지한다. |
| 기존 사건·거래·공공 회계 | 기존 가문 경로도 사건 자격·복지 예산·혁명·체제 변경을 수정했다. 새 엔진은 명령 전체 원자성·명시적 계정과 저장 스키마를 사용한다. |

새 엔진의 모듈: `game.js`(원자적 명령·계획), `economy.js`(상품·고용·물류), `society.js`(주거·집단 평가), `politics.js`(의회·선거·제도), `story.js`(대화·약속), `family.js`(가족·계승), `editor.js`, `schema.js`, `migration.js`. `systems.js`가 일별 처리와 경량 뷰를 연결한다.

## 2. 정합성 — 완료

- 개인·사업·국고·주민·시장·계획 예약 예산을 구분한다. 계획 취소는 미사용 예약액을 원래 계정에 돌려준다. 공공 소유 사업의 개인 청산을 막고, 동업 청산은 상대 지분을 지급한다.
- 모든 새 명령은 실패 시 시간·돈·난수·관계·약속까지 복구한다. 디스크 저장 실패도 이전 게임 상태로 복구한 뒤 오류를 돌려준다.
- 사건의 표시·선택·시간 진행에서 현재 역할·사업·소속·상대·선행 약속을 검사한다. 제작 계획 중 공직을 맡으면 제작 자격을 다시 확인한다.
- 기존 가문 모드의 `dynStoryEligible`·`dynStoryRecheck`가 최고 직위의 직업 사건과 무효 대기 선택을 막는다. `electedFoodPetition`의 복지 예산과 표시 비용을 실제 집행 계정으로 통일하고 선택 시 비용을 다시 계산한다.
- 기존 `revoltRun`의 가문 경로는 1년 준비로 전환했다. `rcAct`도 준비 계획을 저장하고 기간 종료 때 역할·민심·의회·군 지지를 확인한다. `regTick`·자동 봉기는 가문 플레이에서 확률만으로 체제를 바꾸지 않는다. 원래 자유방임 결과는 유지했다.

검증: `check-rebuild.js`, `check-rebuild-systems.js`, `check-rebuild-legacy.js`, `check-contextual-consistency.js`, `check-regime-change.js`, `check-story-fuzz.js`.

## 3. 모바일 핵심 UI — 완료

- 첫 화면에 지역 지도와 선택 장소의 수요·조건·비용·실행을 배치했다. 3개 기본 화면은 마을·내 활동·사람이다.
- 식량·일자리·주거·가격·운송·여론 레이어를 실제 계산값으로 표시한다. 지도 장소는 키보드로도 선택할 수 있다.
- 고용·위임·거래·지역 활동은 대상 패널에서 열고 완료한다. 탭별 스크롤과 선택 장소를 유지한다. 인물 목록은 페이지로 조회하며 전체 주민을 매번 내려받지 않는다.
- 행동 전에 시간·비용·기간·자격과 위험을 표시하고, 중요한 협상은 선택할 때까지 시간이 멈춘다. 결과와 원인은 기록에 남는다.
- 실제 360·390·820px에서 가로 넘침, 첫 화면 개업 버튼, 선택 장소 복귀, 모든 운영 화면과 실제 명령 실행을 확인했다.

검증: `check-rebuild-ui.js`, 기존 화면 `check-mobile-ui.js`.

## 4. 생활·사업·인물 플레이 — 완료

- 3개 지역·9개 부지에서 임대·매입, 식량·공구·의복 생산, 초기 자금·동업·고용·임금·공급·판매처를 조합한다.
- 저가 대량·고품질·안정 납품·숙련 투자·현금 보유 방침을 자동 실행한다. 생산은 노동·원료·재고·현금의 한계를 받는다.
- 지역 간 도로 그래프에서 운송 거리·시간·용량을 계산한다. 원료는 발주 때 돈과 실제 자원을 이동하고, 상품·원료는 도착 후에만 사용 가능하다.
- 주민은 가격·품질과 자신의 현금으로 소비한다. 지역별 실제 소비·가격·고용·임금·주거·교육이 다음 판단과 지지에 반영된다.
- 경쟁자는 수요와 자금에 따라 운영 방침·입지·고용을 바꾼다. 주민의 숙련·야심·충성·관계는 생산·위임·이직에 작용한다.
- 계획은 자금·사람·우선순위를 배분하고, 담당자의 숙련과 이탈에 따라 진행이 달라진다.

검증: 방침별 실제 결과 차이, 운송 도착·공급자 전환, 일상 소비와 회계 보존, 고용·대화·위임·계획 취소 검사.

## 5. 정치 루프 — 완료

- 농민·노동자·상인·지역 주민은 토지·상품 가격·임금·고용·세금·주거·식량·학교·교통을 다르게 평가한다. 집단별 지지와 원인을 표시한다.
- 면담·지역 조직·정당 가입·토론·연설·영입·공약·연대를 선택한다. 주민의 지지·정당·참여와 경쟁 세력이 실제 투표·의석을 결정한다.
- 낙선 후에도 조직·감시·생활 문제 해결·재출마가 가능하다. 상태 주입 없이 첫 낙선 후 조직·토론으로 60일 선거에 당선되는 경로를 검증했다.
- 의회는 세율·구호·최저임금을 심의한다. 집행자는 국고와 행정 역량으로 도로·학교·주거·운송망을 만들고 책임자를 임명한다. 공직은 국고 보수와 겸직 조건을 따른다.
- 공화정·의회 내각제·입헌군주정의 권력 구조와 시장·협동·공공 소유 경제를 구별한다. 개헌·소유 개편에는 15일 준비와 주민·의회·조직·행정·치안 지지가 필요하다. 개헌 뒤에는 새 선거를 열며 준비자가 자동 집권하지 않는다.
- 공공 소유는 국고 배당, 협동 소유는 직원 배당, 사유 소유는 소유자·동업자 배당으로 달라진다. 개편 후 반발·정당성 변화가 남는다.

검증: 집단별 투표·의회 구성, 가결·부결, 국고 집행, 역할 상실, 개헌 준비와 새 선거, 소유권·배당·청산 권한.

## 6. 이야기와 후속 반응 — 완료

- 인물 면담·교육·후원·영입·고용·혼인은 관계와 기억으로 남는다. 직원 협상·책임자 제안·납품·맞춤 제작이 실제 사업·역할에서 발생한다.
- 수락·거절·역제안이 실제 계약의 물량·대금·기간·권한을 바꾼다. 납품은 실제 재고와 구매자의 지불 능력으로 처리한다.
- 확장 사업에 대한 출마 후원 → 독점 납품 약속 → 당선 후 공공 조달 이해충돌 → 공개 철회·개인 합의·특혜의 결과가 이어진다. 관계·신뢰·정당성·예산이 바뀌며 저장 후에도 남는다.
- 대기 사건은 조건이 바뀌면 표시·실행을 막는다. 사소한 완료는 기록으로 묶고 중요한 협상만 장면을 쓴다.

검증: 협상·납품 기한, 직위 변경 시 사건 차단, 후원 약속의 후속 장면과 계정, 관계 기억, 복원 후 동일 진행.

## 7. 가문·장기 성장·재기 — 완료

- 가문 구성원의 나이·부모·혼인·교육·후계·유언·재산을 저장한다. 자녀 양육과 교육에 자원을 쓰고 성년 후계자로 계승한다.
- 균등 분배와 후계자 우선 상속은 재산 분배와 분쟁을 다르게 만든다. 합의·중재·거절은 가족 관계와 자산·신뢰에 남는다.
- 계승은 사업·주거·계약·약속·기술과 관계 일부를 이어간다. 새 가장의 배우자·자녀 관계를 구분하고, 후계자가 없을 때 입양·친족 섭정으로 재기할 수 있다.
- 사업망·생활 안정·세대 명성은 서로 독립적인 성취 목표다. 사업 정리 후 기술·인맥·부지는 남고, 품팔이·주거 변경·대출·상환으로 다시 시작할 수 있다. 연체 채무를 갚기 전에는 새 대출을 제한한다.

검증: 교육·혼인·상속·분쟁, 자연사 후 계승, 3개 시드 각각 1,800일, 동업 권리 정산, 연체 후 상환·신용 회복, 계획·약속·가문 저장 왕복.

## 8. 이미지·저장·성능 — 완료

- 새 삽화는 작은 인라인 SVG라 네트워크 이미지 요청 없이 선명하게 표시된다. 대화·선택지는 그림·타자 연출을 기다리지 않는다. 기존 가문 삽화는 필요한 파일을 먼저 요청·캐시하고 모바일 높이를 제한했다. 기존 원본 1672px 아틀라스를 확대 압축해서 다시 저장하지 않는다.
- 새 저장 v2는 v1을 읽고 필드를 보완한다. 미지원 버전·손상 파일·고용 연결 오류는 거부한다. 명령 성공은 저장 원자 교체 뒤에만 응답한다.
- 기존 마을 가져오기는 먼저 변환 범위를 설명한다. 종전 직위·부동산·지분·계약·사건을 새 규칙에서 임의 실행하지 않는다. 원본 전체(g/q 포함)는 별도 압축 보관하고, 주민과 개인 현금을 새 규칙의 첫날로 옮긴다. 원본 보관본은 전체 내보내기에 포함된다. 기존 게임은 원래 주소·저장에서도 계속 사용할 수 있다.
- 원본 대용량 파일은 일상 저장에 중복 직렬화하지 않는다. 뷰는 요약과 최대 150명의 필요한 인물만 제공하고, 나머지는 페이지·선택 조회를 사용한다. ETag 304와 캐시된 gzip 뷰를 유지한다.
- 실제 HTTP에서 저장 실패의 상태 복구, 진행 중 저장 덮어쓰기 거부, 미래 버전 거부, 전체 가져오기·내보내기 원본 일치, 서버 재시작 복원, 편집 권한·세계 격리를 확인했다.

이 실행 환경의 5,000명 원본 가져오기·10일 진행 측정(`node --expose-gc scripts/check-rebuild-performance.js`): 화면 gzip 16,738바이트, 진행 저장 gzip 217,046바이트, 원본 보관본 6,599,414바이트, 저장 151ms, 하루 명령 57~165ms, 검사 종료 RSS 287,256,576바이트. 단일 로컬 측정이며 AWS 성능 수치가 아니다.

## 운영 상태

구현과 로컬 검증은 PR에서 확인할 수 있다. main 병합·AWS 서비스 재시작·실제 휴대폰에서의 실행은 별도 운영 작업이며 이 기록에서 수행 완료로 표시하지 않는다. 기본 새 게임은 60명 소지역이고, 5,000명 측정은 저장 호환·성능 검증이다.
